# 排序算法的音乐可视化

这是拿AI写的一个可视化音频排序小游戏。

把一张图横向切成 N 片、打乱顺序，然后用排序算法把它「排回来」——每比较一次就播放这一片图对应的那段音频，排完播放整首歌。

AI真是太好用了.jpg

## 在线地址

https://dzycd.github.io/SortingVoice/

## 本地预览

预设音频是用 `fetch` 加载的，直接双击 `index.html`（`file://`）会被 CORS 拦掉，需要起个静态服务：

```bash
python -m http.server 5173
# 或 npx serve -l 5173
```

然后打开 http://127.0.0.1:5173/ 。

## 目录

- `index.html` —— 全部逻辑（无构建步骤，纯静态）
- `image/*.webp` —— 预设图片（2048×1024，页面 canvas 最宽只渲染 1000px）
- `image/*.png` —— 预设图片的原始 4096×2048 母版，保留备查
- `music/*.mp3` —— 预设音频

## 更新记录

### 资源瘦身

3 张预设图 4096×2048 PNG 共 21.5 MB → 转成 2048×1024 WebP（质量 82）共 720 KB，首屏传输量降到原来的 **3.3%**。

### 逻辑修正

- **进度条**：原来按「值 == 下标」的切片数算，插入/归并/堆排序时几乎恒为 0。现在每种算法都写成生成器，先在副本上预演一遍得到精确总步数，动画阶段用 `已完成步数 / 总步数` 推进，任何算法都单调走到 100%。
- **统计口径**：新增「写入次数」；比较次数按真实比较次数计（含循环最后一次失败比较）；插入排序改用相邻交换实现，`交换次数` 才是真实交换次数。
- **音爆**：每个音频片段加 8ms 淡入/淡出包络，不再直接截断 PCM。
- **音源泄漏**：所有正在播放的 `AudioBufferSourceNode` 统一登记，停止/打乱/重开时回收；停止后不再有残留声音。
- **归并排序显示**：已确定前缀只写进渲染覆盖层，整块算完一次性原子提交。任意时刻切片都是合法排列，中途停止不会留下重复切片。
- **中途停止**：停止后 `isRunning` 由驱动循环统一复位（原来在按钮回调里提前复位，快速连点会让两个循环同时改同一个数组）。
- **其他**：堆排序的比较阶段补了动画帧（原来视觉跳步）；换图/换音频会重置统计并禁用「开始」直到重新打乱；运行中禁用切片数量与算法下拉框。
